## 완료된 구현

- CLI와 plugin/marketplace version은 `0.4.0`이다.
- `start/send`의 turn lifecycle을 공통 구현으로 정리했다.
- durable `GLM_RESULT_FILE` contract와 외부 `system-prompt.md` 직접 읽기를 구현했다.
- `start --async`, `send --async`, `wait`, `cancel`, managed `tui` 신규/attach를 구현했다.
- worker별 동일 Claude session, 원래 cwd/model/role 유지, raw response/stderr/result/history 보존을 구현했다.
- detached runner와 provider process group, generation-scoped cancel, runner/provider start identity 검증을 구현했다.
- atomic meta/active update, stale/reused runner recovery, sync signal forwarding, Z.ai error classification을 구현했다.
- `close`와 turn 시작을 active lock으로 직렬화하고 turn 준비가 lock 획득 뒤 `closed`를 재검증한다.
- concurrent stale finalizer는 `active/finalizing` claim 하나만 획득한다. claim owner PID/start identity가 죽으면 후속 lifecycle 명령이 claim을 원자적으로 치환하고 복구한다.
- provider leader가 사라져도 소유한 process group을 TERM→KILL로 정리하며 zombie/leader-disappearance TOCTOU와 다른 PID start identity를 구분한다.
- 정상 성공 turn은 provider group을 drain하지 않아 worker가 검증하고 남긴 persistent background process를 보존한다. cancel·signal·provider error·protocol invalid에서만 drain한다.
- 명시적인 `subtype=success`, `is_error=false` 응답은 자유형 result의 Z.ai/code 문장보다 우선한다. 구조화된 error object/is_error/subtype error는 계속 오류다.
- worker snapshot은 active state 전체를 전후 비교하고, state 없는 active directory와 turn/supervision 미게시 상태를 retry한다. active 없음은 meta 전후 일치와 active 재확인을 요구한다.

## 독립 리뷰 기록

- 첫 리뷰: generation ABA/PID reuse, non-atomic metadata, stale runner, sync orphan, exit-zero error shape, Bash 3.2 문제를 지적했고 모두 수정했다.
- 두 번째 리뷰: concurrent finalizer, leaderless group, snapshot TOCTOU, broad result detector, close race를 지적했고 모두 수정했다.

## 주의점

- API key를 stdout/stderr, diff, commit에 노출하지 않는다. 인증은 `~/.glm/.env.auth`를 그대로 사용한다.
- `CLAUDECODE`는 provider invocation에서 unset 상태를 유지한다.
- `system-prompt.md`는 worker마다 복사하지 않고 매 turn 현재 파일을 직접 읽는다.
- 정상 완료된 persistent background service를 wrapper가 임의로 종료하지 않는다. `RUNNING` receipt 자체는 완료가 아니지만, worker가 실제 검증 후 `STATUS: DONE`을 쓴 뒤 남긴 서비스는 정상 산출물일 수 있다.
- user-scope 규칙에 따라 shell에서 `cd`를 직접 사용하지 말고 command workdir 또는 subshell을 사용한다.
